# Настройка отправки Email для подтверждения заказов

## Что реализовано

Теперь при создании заказа автоматически отправляются email:
- **Клиенту**: красивое письмо с подтверждением заказа и всеми деталями
- **Админу**: уведомление о новом заказе с контактами клиента

Письма отправляются как для авторизованных пользователей, так и для гостей.

## Измененные файлы

### 1. Frontend
- **`src/pages/Checkout.tsx`**
  - Добавлен вызов Edge Function `send-order-confirmation` после создания заказа
  - Реализована обработка ошибок (не блокирует оформление заказа)
  - Добавлено логирование результатов отправки email

## Настройка переменных окружения

### Шаг 1: Получите API ключ от Resend

1. Зарегистрируйтесь на [resend.com](https://resend.com) (бесплатно)
2. Перейдите в [API Keys](https://resend.com/api-keys)
3. Создайте новый API ключ
4. Скопируйте ключ (начинается с `re_`)

### Шаг 2: Настройте секреты в Supabase

**Важно:** Edge Function уже задеплоена, но нужно добавить секреты.

#### Через Supabase Dashboard:

1. Откройте ваш проект в [Supabase Dashboard](https://supabase.com/dashboard)
2. Перейдите в **Settings** → **Edge Functions**
3. Нажмите **Add secret**
4. Добавьте следующие секреты:

| Название переменной | Значение | Описание |
|---------------------|----------|----------|
| `RESEND_API_KEY` | `re_xxxxxxxxxx` | Ваш API ключ от Resend |
| `FROM_EMAIL` | `onboarding@resend.dev` | Email отправителя (для тестирования) |
| `ADMIN_EMAIL` | `your-admin@email.com` | Ваш email для получения уведомлений |

#### Для тестирования используйте:
```
RESEND_API_KEY=re_ваш_ключ_здесь
FROM_EMAIL=onboarding@resend.dev
ADMIN_EMAIL=ваш_реальный_email@gmail.com
```

**Примечание:**
- `onboarding@resend.dev` - это тестовый email от Resend, работает сразу без настройки домена
- Письма с него могут попадать в спам, но для тестирования подходит

### Шаг 3: Для продакшена - настройте свой домен

Когда будете готовы к продакшену:

1. В Resend добавьте свой домен (Settings → Domains)
2. Добавьте DNS записи (MX, TXT, CNAME) в настройки вашего домена
3. Дождитесь верификации домена (обычно 5-10 минут)
4. Обновите секрет `FROM_EMAIL` на email с вашим доменом:
   ```
   FROM_EMAIL=orders@yourdomain.com
   ```

## Проверка работы

### 1. Тестирование локально

После добавления секретов в Supabase:

1. Откройте сайт и добавьте товар в корзину
2. Перейдите к оформлению заказа
3. Заполните форму с **реальным email**
4. Оформите заказ
5. Проверьте:
   - В консоли браузера должны появиться логи `[EMAIL] ...`
   - На указанный email должно прийти письмо с подтверждением
   - На `ADMIN_EMAIL` должно прийти уведомление о заказе

### 2. Проверка логов в Supabase

1. Откройте Supabase Dashboard
2. Перейдите в **Edge Functions** → **send-order-confirmation**
3. Откройте вкладку **Logs**
4. Вы должны увидеть логи с результатами отправки:
   ```
   [ORDER CONFIRMATION] Starting email send process
   [ORDER CONFIRMATION] Processing order: xxx for email: xxx
   [ORDER CONFIRMATION] Order fetched successfully
   [RESEND SUCCESS] { id: "..." }
   [ORDER CONFIRMATION] Customer email sent successfully
   [ORDER CONFIRMATION] Admin email sent successfully
   ```

### 3. Что делать, если письма не приходят

1. **Проверьте спам** - письма от `onboarding@resend.dev` часто попадают в спам
2. **Проверьте логи** в Supabase Edge Functions
3. **Проверьте консоль браузера** - там должны быть логи успеха/ошибки
4. **Проверьте секреты** - убедитесь, что `RESEND_API_KEY` правильный
5. **Проверьте квоту** - бесплатный план Resend: 100 писем/день

## Лимиты Resend (бесплатный план)

- **100 писем в день**
- **1 домен**
- **Неограниченное количество API ключей**

Этого достаточно для тестирования. Для продакшена рассмотрите платный план.

## Формат писем

### Письмо клиенту содержит:
- Красивый дизайн с gradient header
- Номер заказа
- Таблица с товарами, количеством и ценами
- Итоговая сумма
- Адрес доставки
- Контактные данные
- Способ оплаты

### Письмо админу содержит:
- Номер заказа
- Контактные данные клиента
- Адрес доставки
- Детали заказа
- Способ оплаты
- Итоговая сумма

## Безопасность

- Edge Function использует `verify_jwt: false` (публичная функция)
- Service Role Key используется **только на бэкенде** для чтения заказов
- На фронтенде используется **только Anon Key**
- RLS политики остаются включенными
- Если отправка email падает - заказ все равно создается

## Дополнительные настройки (опционально)

### Netlify Environment Variables (если используется)

Переменные `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` уже должны быть настроены в `.env` и Netlify. Проверьте, что они правильные:

1. В Netlify: **Site settings** → **Environment variables**
2. Убедитесь, что есть:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`

## Поддержка

Если возникли проблемы:
1. Проверьте логи в Supabase Edge Functions
2. Проверьте консоль браузера (F12)
3. Проверьте, что секреты правильно настроены
4. Убедитесь, что в Resend есть активный API ключ
